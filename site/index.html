v0.2.0: an experiment

A comfortable ML, without a garbage collector.

Yack is a language in the ML family, close to SML and OCaml. It is meant to be pleasant to write: the syntax keeps the same shape, and the only ceremony it adds is what the types require. Affine and linear types, together with the ownership rules Rust popularised, take the place of the garbage collector. The compiler checks ownership in the frontend, places each free deterministically, and lowers the program through LLVM to a native binary.

01. Language

A small core with inferred types

The core is deliberately narrow: module-level functions, recursion, case, records, tuples and generic datatypes, with no classes, loop syntax or capturing closures. Integer literals are checked against the width they are used at, so a value that does not fit is a compile error.

Inferred types

Hindley-Milner inference with 'a and ''a generics; numeric constraints are resolved and generic functions monomorphised at compile time.

Pattern matching

Nested case expressions, guards, exhaustiveness checking, and patterns for lists and strings.

Modules and packages

Imports can be qualified, selective or aliased. Local dependencies live in a plain yack.toml.

Useful diagnostics

Every error has a stable code, a span, a note and often a suggestion.

02. Examples

Four small example programs

Lists, modules, datatypes and diagnostics. All four examples go through the same frontend, type checker and ownership rules. The grey hints show inferred types; hover one, or the underline in the last example, to see what the language server reports.

sum.yack 2 hints 
fun sum (values : int list) : int =
    case values of
        [] => 0
      | head : int :: tail : int list => head + sum (tail)

fun main () =
    print_int (sum ([1, 2, 3]))
→ 6

03. Memory

Every value declares how it is used

Each value is Copy, Affine or Linear. The compiler tracks moves and borrows, then places free after the last owner.

render.yack 
fun render (request : string) : string =
    arena
        val path = string_slice (borrow request, 0, 8)
        val body = "hello " ^ path
    in
        body
    end

At end, the block's temporaries are released at once. A temporary value cannot escape the block.

  • No collector. Ownership and lifetimes decide when memory is released, so frees stay deterministic. The annotations the model adds are the ceremony the types require.
  • Checked borrows. A borrow is shared or mutable, its provenance is explicit, and conflicting loans are reported.
  • Temporary arenas. Request-scoped memory can be released in one step at the end of a block, without leaving the language model.
  • Checked again after lowering. After lowering, every function is rebuilt as an SSA graph and ownership is checked again on every path: each owned value is freed exactly once and never used afterwards.
  • Pass-through allocations. The graph knows the last use, so a ^ b ^ c chains fuse and an accumulator grows in place instead of being copied.
  • Failures stop the program. An allocation that cannot be served aborts with [yack] out of memory. Integer overflow aborts instead of wrapping, and a thread that cannot be created is reported. There is no silent null pointer.

yack arena, yack alloc-map and --trace-alloc show what is allocated, freed or kept.

04. Tools

The compiler and its tools

yack new

Creates a project from a template: hello, cli, web or tui.

yack check

Runs the lexer, parser, resolution, types and ownership. It prints nothing when the program is fine.

yack fmt

Rewrites a file in one canonical form. A second run changes nothing.

yack build

Lowers the typed IR to LLVM, calls clang, and writes a native executable.

yack run

Builds and runs the project entry, or a single file.

yack lsp

Diagnostics, inlay hints, completion, hover and quick fixes; go to definition, references and rename across files; semantic tokens, signature help, call hierarchy and formatting. It is a native binary, so it does not need Node.

The standard library has 29 modules, including six that reach the system: yack/fs for directories and metadata, yack/file for streaming handles, yack/process for running programs, yack/net for DNS and TCP, yack/time for clocks and dates, and yack/random for kernel random bytes. They use an extern mechanism reserved for the standard library; descriptors are opened with O_CLOEXEC, interrupted calls are retried, and errors carry the errno in a result value.

The same program in four languages

Each version implements the same contract: an optional --name value, Yack as the default, one greeting, and a usage error on an unknown flag. Every version uses its language's idiomatic parser. flag and clap print that error and exit inside the parser; Yack returns it as a value, so the branch appears in the source. 

import yack/args
import yack/io
import yack/option
import yack/os

(* A CLI: `app --name Ada` prints a greeting. *)
fun main () =
    case args.parse (
        [args.Opt (("name", None, "who to greet", Some ("Yack")))],
        os.command_args ()
    ) of
        Error message => io.eprint_line (borrow message)
      | Ok parsed =>
          let val name = args.get_option (parsed, "name") |> option.unwrap_or ("Yack")
              val line = "Hello from " ^ name ^ " !"
          in
              io.print_line (borrow line)
          end

The option is a declared args.spec: the flag name, its help text and its default live in one value, and usage is generated from it. A bad flag comes back as an Error value, so the caller handles it; option.unwrap_or owns the default. 

package main

import (
	"flag"
	"fmt"
)

func main() {
	name := flag.String("name", "Yack", "who to greet")
	flag.Parse()
	fmt.Println("Hello from " + *name + " !")
}

Go's flag does the same job with the standard library, and memory stays the garbage collector's concern. 

const args: string[] = process.argv.slice(2)
const index: number = args.indexOf("--name")
const name: string = index === -1 ? "Yack" : args[index + 1]
console.log(`Hello from ${name} !`)

Shortest to write, but the program is a script: it needs a runtime (Node or Bun) on the machine that runs it. 

use clap::Parser;

/// A CLI: `app --name Ada` prints a greeting.
#[derive(Parser)]
#[command(name = "app")]
struct Args {
    /// who to greet
    #[arg(long, default_value = "Yack")]
    name: String,
}

fn main() {
    let args = Args::parse();
    println!("Hello from {} !", args.name);
}

clap with derive: the struct is the spec, the same shape as args.spec. Ownership is checked like in Yack; the binary carries clap with it.

06. Web

Alpage, a web framework in Yack

Alpage is written in Yack. Handlers are ordinary functions, the request is moved into the handler that owns it, errors are values, and an application can be tested without opening a socket.

src/Api.yack 
fun application () : Alpage.t =
    Alpage.new ()
    |> Alpage.get ("/", home)
    |> Alpage.get ("/hello", hello)
    |> Alpage.get ("/greet", greet)
    |> Alpage.get ("/square/:n", square)
    |> Alpage.post ("/sum", sum)
    |> Alpage.get ("/admin", admin)
    |> Alpage.with (Alpage.log ())
    |> Alpage.with (Middleware.before (require_token))
    |> Alpage.with (Middleware.security_headers ())
  • From another language. The tutorial puts each step next to the code you would write in Go, TypeScript or Gleam.
  • One owner per request. Reading a request twice is a compile error, so that bug cannot reach run time.
  • Tests run without a socket. The same application value runs on the server and in the test client.
  • Clean shutdown. The HTTP server handles SIGINT and SIGTERM, closes the listener and every connection, and returns Ok (). It also closes slow, idle and non-reading connections, and a hostile-client fuzzer runs in the test suite.

07. Status

Status of the project

Yack is still an experiment: a language in the ML family, with ownership checked in the frontend and native code, a web framework and a language server built around it. The parts that exist are tested under AddressSanitizer, ThreadSanitizer and fuzzing; the table below marks everything else.

It is not ready for production. The runtime blockers from the last audit are fixed: out-of-memory allocations abort with a message, thread creation failures are reported, and the HTTP server shuts down cleanly and backs off on EMFILE. Still missing: a stable, versioned standard library API (everything is 0.1.0), targets other than Linux x86-64, a language server that a malformed message cannot crash, an HTTP server that accepts requests and responses larger than 4 KiB (larger ones are currently dropped), and CI running the test suites. It fits experiments, tools and side projects, not a service someone depends on.

08. Quick start

Build and run a first project

The compiler needs MLton, and yack build needs clang. Node or Bun is only used by the tests. Only Linux x86-64 is supported as a target: yack build refuses any other platform with an explicit error.

terminal 
# build the compiler
make

# a minimal program, or a starting point:
./yack new hello
./yack new hermes --template cli   # hello | cli | web | tui
cd hermes
../yack run

The prebuilt yack-linux-x86_64.tar.gz on the releases page ↗ finds lib/ by itself, or through YACK_LIB.
